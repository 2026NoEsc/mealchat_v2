## 수정 내용

- 키보드 제출과 전송 버튼을 빠르게 연속 사용해도 처리 중인 메시지를 중복 전송하지 않는다. 같은 잠금을 이모티콘 전송에도 적용했다.
- 전송 중 편집한 입력은 이전 요청이 완료돼도 보존한다. 지웠다가 같은 문구를 다시 입력한 경우도 구분한다.
- 요청 실패 시 입력과 재시도 가능 상태를 유지한다.
- 채팅의 `ScrollView` 전체 렌더링을 `FlatList` 가상화로 교체했다. 최신 메시지부터 초기 렌더링하며 메시지 ID와 날짜에 기반한 키를 사용한다.
- 입력할 때 메시지 데이터와 행 렌더 함수를 재생성하지 않고, 행은 `memo`로 보호한다.
- 과거 메시지를 읽는 중에는 콘텐츠 크기 변경으로 최신 메시지 위치로 강제 이동하지 않는다.
- 폰트 로딩 실패 시 빈 시작 화면에 머무르지 않고 앱 렌더링을 계속한다.

채팅 테스트는 실제 화면 컴포넌트와 React Native `FlatList`를 React test renderer로 렌더하고 서버 호출을 mock한다. 1,000개 메시지 fixture에서 초기 렌더되는 메시지가 100개 미만임을 확인했다. 이 결과는 실기기 FPS·메모리 측정이나 운영 서버 송수신 성공을 의미하지 않는다.

번들은 `.env` 자동 로드를 끄고 가상 Supabase 설정으로 `dist/stability-2026-10-02/`에 생성했다. 배포용 인증 설정을 포함한 실행 파일이 아닌 로컬 번들 검증 산출물이다.

## 남은 확인 사항

- 의존성 감사는 수정 전후 모두 실패했다. 신규 미허용 권고 18개와 2026-09-30 만료 예외 4개가 보고됐다. 별도 `npm audit`의 패키지 집계는 high 5개, moderate 13개이며 권고 개수와는 집계 단위가 다르다. 의존성 버전이나 감사 예외는 변경하지 않았다.
- 일부 자동 수정안은 Expo 주요 버전 변경을 제안한다. 호환성 검증과 영향을 받는 보안 경계의 독립 리뷰를 거쳐 별도 변경으로 처리해야 한다.
- `adb devices`에 연결된 기기가 없었다. 가변 높이의 말풍선·이미지, 키보드, 과거 대화 스크롤 위치는 Android/iOS 실기기에서 추가 확인해야 한다.
- 이번 가상화는 화면 렌더링 범위만 줄인다. `fetchRoomMessages`의 전체 조회는 그대로이므로, 서버 응답 상한을 넘는 긴 대화에는 페이지 단위 조회가 후속 과제다.
- Auth·AI 추천·정산·원격 데이터 격리의 운영 E2E 검증은 이번 결과에 포함하지 않는다.
